Databricks 模型/产品发布 AI 产品与工具 Databricks

Databricks 宣布 Lakebase Postgres 在 Google Cloud 上正式可用，生产级无服务器 Postgres 直接运行于 Data + AI 平台。

事实摘要

Databricks 宣布 Lakebase Postgres 在 Google Cloud 上正式可用（GA），团队可在其 Data + AI 平台上直接运行生产级无服务器 Postgres，计算与存储分离，并与分析数据共享同一存储层、免去管道维护。

服务包含自动扩缩容与归零、秒级零拷贝分支、时间点恢复、标准 Postgres 生态（含 pgvector 兼容搜索），并通过 Unity Catalog 统一治理；多区域高可用端点 SLA 为 99.99%。

官方测试数据显示 Lakebase Search 相比 pgvector 吞吐提升 2 倍、成本降低 4 倍，1TB 数据写入加载不到 5 分钟；这些性能数字来自厂商自测，尚无独立验证。 客户 KaBuM! 已将其用作 AI 智能体的默认记忆层；

GA 首发区域为 asia-southeast1、europe-west3、us-central1、us-east4、us-west1。

编辑解读

Lakebase 是 Databricks LTAP（湖事务/分析处理）架构的关键组件，本次 GA 意味着该架构的核心存储服务进入生产可用阶段。

公告同时披露了 Private Service Connect 私有连接（Beta）与 OAuth/统一身份认证等企业级功能，可后续观察其落地情况。

Circle K Agent/开发者基础设施 AI + 行业赋能 aws

Circle K 用 Amazon Bedrock Agent 将 DevOps 事故分诊时间从 45–60 分钟降至 15 分钟内。

事实摘要

Circle K 的 DevOps 团队在 AWS 官方博客公布，他们用 Amazon Bedrock 构建了自动化事故分诊系统，将平均分诊时间从 45–60 分钟降至 15 分钟以内，降幅为 67–75%，数据来自团队内部事故响应指标。

系统最初用 Amazon Bedrock Flows 编排，包含并行查询 AWS 资源、OpenSearch 日志与 GitHub 仓库的三个专用 agent，再由 AnalysisPrompt 汇总为包含根因、证据、负责人和修复建议的结构化摘要并发送到 Slack，全程耗时 5–15 分钟。

随着日志与知识库增长，团队迁移到 Amazon Bedrock AgentCore：将三个 agent 合并为一个在 AgentCore Runtime 会话中运行的 agent，支持最长 8 小时会话并通过 AgentCore Gateway 统一代理数据源访问，简化了访问控制和扩展。

编辑解读

这是一家零售能源企业的生产环境案例，而非 AWS 或 Bedrock 的新产品发布；报道主体是 Circle K 的落地实践，应当放在 Agent 工程实践与运维 agent 应用场景下阅读。

01
Andrej Karpathy 行业动态 AI + 行业赋能 补录 · 2026-11-01 发布 Andrej Karpathy

HackerTube. I was annoyed with YouTube's recommendations so I had Claude filter down 43M comments over 20 years of HN to 6,454 videos that keep being recommended. *Significantly* better viewing experience, ~2 hours with Opus 5.5: https://t.co/JIhXN7OSh1 - Excellent recs without any logins (state is kept in local browser session) - Thumbnail is a representative frame from middle of the video instead of the super duper A/B test hyper-optimized user uploads - Underlying data from the comment analysis as one zip file, point your Claude at it and ask for your own version - HackerTube Longs ✊ A bit more on the process: I use Claude Code (desktop app for Mac), Opus 5.5 on Medium effort as my default. I only talk to Claude and have it do everything, the only "manual work" I helped with in tandem was in the browser (reminiscent of MenuGen): 1) I had to create some kind of API key from Google Cloud UI to query YouTube for video metadata, 2) I booted up a VPS box for serving and 3) I bought the domain name. Once the box was up I gave Claude the IP and told it update, secure, harden, deploy and optimize the code, and it did the whole thing. Many awesome projects that would have normally taken weeks/months even can now be few-shotted for breakfast. What else are we not thinking of.

译文

HackerTube。我对 YouTube 的推荐感到烦了，于是让 Claude 把 HN 20 年来的 4300 万条评论筛选出 6454 个一直在被推荐的视频。

*明显*更好的观看体验，用 Opus 5.5 大约花了 2 小时： https://t.co/JIhXN7OSh1 - 无需任何登录即可获得出色的推荐（状态保存在本地浏览器会话中） - 缩略图是视频中间的代表性帧，而不是那些经过超级 A/B 测试超优化的用户上传缩略图 - 评论分析的底层数据打包成一个 zip 文件，让你的 Claude 读取它，让它生成你自己的版本 - HackerTube Longs ✊ 再补充一点过程： 我用 Claude Code（Mac 桌面应用），默认使用 Opus 5.5，Medium effort 模式。

我只和 Claude 对话，让它做所有事情，我唯一手动配合的部分是在浏览器里（有点像 MenuGen）：1）我不得不从 Google Cloud UI 创建某种 API 密钥来查询 YouTube 的视频元数据，2）我开了一台 VPS 用于托管，3）我买了域名。

服务器起来后，我把 IP 给 Claude，告诉它更新、加固、部署并优化代码，然后它就把整件事都干了。 很多通常需要几周甚至几个月的超棒项目，现在用 few-shot 就能像吃早餐一样轻松搞定。还有什么我们没想到的呢？

WIRED 指南：AI 搜索适合常见问题与复杂查询，精确细节与高风险场景仍宜用传统搜索。

事实摘要

WIRED 撰文梳理 Claude、ChatGPT、Gemini 等 AI 聊天机器人用于网页搜索的适用边界：简单且广为人知的问题，以及需要综合多个来源的复杂查询（如按预算选择餐厅），AI 搜索通常表现良好。

文章转述斯坦福大学研究称，AI 在找到准确来源后提取信息的能力较强，短板在于找不到准确来源时仍会给出自信的回答；加州大学圣迭戈分校研究发现，AI 搜索可能按查询相关度而非权威性选择来源。

本篇为观点与实用指南类报道，梳理 AI 搜索与传统搜索的适用边界，未发布新模型、产品或评测数据；可作为观察 AI 搜索产品形态及用户替代行为的背景素材。
