OpenAI 模型/产品发布 政策、安全与社会影响 The Decoder

OpenAI 发布 GPT-6 Cyber 网络安全模型：官方称发现 Firefox 81 个未知严重漏洞，并为其中 948 个 Linux 内核漏洞开发可用利用程序。

事实摘要

OpenAI 于 2026 年 11 月 5 日发布 GPT-6 Cyber，一个专门训练用于发现软件漏洞、开发可用利用程序并建议补丁的网络安全模型。

官方称该模型在 Firefox 中发现 81 个此前未知的严重漏洞，Mozilla 已接受报告并发布修复；

在 Linux 内核中复现 1724 个漏洞，并为其中 948 个开发可用利用程序，约是 GPT-5.6 Sol 在相同条件下 166 个的五倍多。

在 ExploitGym 基准上 GPT-6 Cyber 得分为 48.5%，高于 GPT-5.6 Cyber 的 32.1%；OpenAI 还称在无特殊安全指令时 99.93% 测试避免越界，启用安全指令后为 100%。

这些基准数字均由 OpenAI 自报，尚无独立测试发布；OpenAI 将其在自家 Preparedness Framework 网络安全类别中列为 Critical，初期仅通过 API 和 Codex 向 Daybreak Red 部分客户开放。

编辑解读

编辑要点是：能力数字与真实漏洞结果均来自 OpenAI 自报，最初仅向部分 Daybreak Red 客户开放，在独立复现前不应把它当作已验证的行业级安全能力。

云服务 11 月 20 日关停意味着现有用户要先迁移，整合成效取决于 Meta 何时把它并入 Muse Code 等自家开发者产品。

事实摘要

vLLM 博客称已对 Kimi K3.1 Pro 实现 Day-0 支持，覆盖 NVIDIA、AMD、Google TPU 和阿里 T-Head Zhenwu PPU。

Kimi K3.1 Pro 是 2.8T 参数（104B 激活）的多模态 MoE，支持 1M token 上下文，并在 24 个全注意力层加入 DSA 稀疏注意力。

vLLM 将每块的 MLA latent、indexer keys 与 KDA state 打包进同一 KV cache，支持 FP8 或 NVFP4 KV 以及可选 MXFP4 index keys，P/D 分离可原样传输。

编辑解读

Kimi K3.1 Pro 在 K3 的 KDA+MLA 混合结构上给 24 个全注意力层加 DSA，vLLM 的 Day-0 适配主要围绕这一变化展开。

开源基准 CloudOpsBench：45 项 AWS 运维任务最佳模型仅完成 60%，作者称主要瓶颈是推理

事实摘要

据 The Decoder 11月4日报道，密歇根大学 Ang Chen 团队发布开源基准 CloudOpsBench，1.0 版本包含 45 项 AWS 云运维任务，由有经验的 DevOps 工程师构建。

测试中表现最好的 Claude Fable 5.1 完成 60%，GPT-6 Astra 完成 53%，没有模型能完成全部任务。 团队称约 80% 的失败源于推理问题，包括误判任务范围、未检查所有相关服务或过早停止；

编辑解读

云运维 Agent 的短板更多不在知识调用，而在任务边界判断与跨服务核查；这批任务的误操作中还有不可逆后果，说明产品侧护栏与确认环节比单纯堆模型能力更能决定可用性。

vLLM 为 Moonshot Kimi K3.1 Pro 提供 day-0 支持，覆盖英伟达、AMD GPU、Google TPU 与阿里平头哥真武 PPU，并给出稀疏注意力的打包 KV 缓存实现。

事实摘要

vLLM 官方博客称已为 Moonshot AI 的 Kimi K3.1 Pro 提供 day-0 支持，覆盖 NVIDIA GPU、AMD GPU、Google TPU 和阿里平头哥真武 PPU。

Kimi K3.1 Pro 是总参数 2.8T、激活 104B、上下文 1M 的多模态 MoE，本次主要改动是在 24 层 MLA 全注意力层加上 DSA 索引器，保留 KDA+MLA 混合结构。

工程上，vLLM 把每块的 MLA latent、索引键与 KDA 状态打包进同一条缓存行，并在 8× GB300 上用按 token 切分的 prefill，把 340K token 的首 token 时延从按 head 切分的 15.89 秒降到 9.42 秒，快 1.69 倍。

vLLM 官方给出的吞吐是 GB300 上每用户最高 375.9 tok/s、每 GPU 37.8K tok/s，Rubin 上每用户 815.6 tok/s、每 GPU 68.7K tok/s，均取自 SemiAnalysis AgentX 基准；

同时 vLLM 与 Megatron 的 log-prob 逐位一致，使 100 步全模型训练的 PPO KL 为 0。

编辑解读

长上下文稀疏注意力服务的瓶颈正从算力转向 KV 布局和跨卡通信，打包缓存与按 token 切分 prefill 是这次适配的实际看点，而不只是又一次 day-0 适配。

文中延迟与吞吐均为 vLLM 自家在 8× GB300 等配置下的测试，缺少第三方复现与其他推理框架的横向对比，采用前需按自己的负载重测。

LangChain 为 Deep Agents 推出异步子 Agent，支持后台长任务并行与审批通知。

事实摘要

LangChain 在博文中宣布，Deep Agents 新增异步子 Agent：orchestrator 保持与用户交互，子 Agent 作为后台 worker 执行长任务并在完成后回报。

该设计把会阻塞 ReAct 循环的长工具调用改为立即返回、后台运行，并用启动、状态查询、更新、取消和列表五个工具管理任务，更新策略可选 interrupt 或 enqueue。

异步子 Agent 已可在 Python、JavaScript 版 Deep Agents 和 Managed Deep Agents 中使用，任务通知仍为 beta，API 可能变化。

编辑解读

对开发者而言，这套接口把 Agent 的并发能力从单条循环长度转向后台 worker 数量，适合长任务和多任务工作流；但通知仍是 beta，任务状态、取消和审批路径仍需在上层处理一致性。
