Databricks 宣布 Lakebase Postgres 在 Google Cloud 正式可用，主打无服务器扩展与 Unity Catalog 统一治理。

事实摘要

Databricks 宣布 Lakebase Postgres 在 Google Cloud 正式可用（GA），可在 Databricks Data + AI 平台运行生产级无服务器 Postgres，计算与存储分离，并与分析数据共享同一存储层。

GA 版本提供自动扩缩容与空闲归零、即时零拷贝分支、时间点恢复（PITR）、标准 Postgres 兼容及 Unity Catalog 统一治理；

厂商自测称 Lakebase Search 相较 pgvector 吞吐 2 倍、成本低至四分之一，1TB 数据加载少于 5 分钟；多区域高可用端点提供 99.99% SLA。

Google研究团队（含斯坦福、牛津等合作机构） 研究/Benchmark Agent 技术 补录 · 2026-11-01 发布 The Decoder

Google研究团队提出视频代理StreamVibe：在做饭或组装家具时自行判断何时开口提供帮助。

事实摘要

11月1日报道，Google与斯坦福、牛津等高校组成的研究团队提出视频代理StreamVibe，让AI在观看用户做饭或组装家具等日常任务时自行判断何时开口帮助，而非只响应诸如“水开了告诉我”这类明确指令。

团队自建了约4,100个示例、来自183小时以上生活与软件录制的基准，先用Gemini 2.5 Flash生成帮助建议，再由四名人类评估者全票通过每个示例。 据论文，StreamVibe-VL基于阿里Qwen3.5-9B训练、每秒判断是否开口；

研究人员称其响应时机与质量比其他模型提升10.7%，记忆系统设计上再带来12.3%的主动互动提升并减少不必要打断，但随视频变长所有模型正确时机的命中率显著下降，连续运行中错误累积使内容质量指标最多下滑61.5%。

论文作者承认，真实场景很可能比测试设置更复杂，未来将研究用户偏好与环境随时间相互影响的问题。

编辑解读

这是Google在agent式视频分析上的延续：9月已为Gemini加入由模型自行决定细看哪些场景的视频分析，StreamVibe把判断从“看哪里”推进到“何时主动开口”，不过论文只描述了研究系统，未涉及产品发布。

02
Circle K Agent/开发者基础设施 AI + 行业赋能 aws

Circle K 基于 Amazon Bedrock 的 Agent 编排将 DevOps 事件初判平均耗时降至 15 分钟以内。

事实摘要

Circle K 在 AWS 官方博客披露其基于 Amazon Bedrock 构建的 Agentic 自动事件初判系统：Grafana 告警经 SNS/SQS 与 Lambda 进入由 AWSResourceExplorerAgent、OpenSearchExplorerAgent、GitHubExplorerAgent 组成的编排流程，最后由 AnalysisPrompt 生成含根因、证据、负责人与修复建议的结构化摘要并推送到 Slack。

据团队内部事故响应指标，部署后平均初判时间降至 15 分钟以内，较文章描述的 45–60 分钟人工排查基线下降 67%–75%；完整链路从告警触发到 Slack 消息耗时 5–15 分钟。

该团队随后从 Amazon Bedrock Flows 迁移到 AgentCore Runtime，把三个专用 Agent 合并为可在最长 8 小时单次会话中运行的单一 Agent，并由 AgentCore Gateway 统一代理对 OpenSearch、知识库和 GitHub 等数据源的访问。

编辑解读

该案例是 AWS 官方博客与 Circle K 工程师合著的一手客户案例，67%–75% 的缩减来自甲方内部指标而非独立第三方评估，引用时需保留归属；文中的 45–60 分钟是文章描述的通用人工排查时长，不可直接按 Circle K 改造前基线引用。

01
Harrison Chase / LangChain 行业动态 Agent 技术 langchain

LangChain CEO发文：常驻proactive agent时代带来新一轮context engineering挑战。

事实摘要

LangChain CEO Harrison Chase发文称，行业正收敛到“LLM在沙箱里循环调用工具”的同一种agent架构，但过去几个月所有agent构建者都在转向proactive、常驻、目标导向的agent，这带来新一轮context engineering挑战。

他列出六个尚无通用解法的问题：主动推送与打扰的平衡、决定“记住什么”的记忆智能层、异步工具与subagent的结果通知与主agent生命周期管理、目标拆解与长期一致性、目标优化可能被agent以意外方式作弊（如“清空所有bug”导致删库），以及浏览器比bash更复杂带来的上下文管理难题。

他承认此前已有不少标准化的context engineering实践，如长线程摘要、大工具结果卸载、skills渐进式披露、工具搜索、subagent上下文隔离与bash作为主工具，并表示几个月前还可能同意“没有多少开放问题”的说法。

编辑解读

这是一篇观点性工程博客，不代表LangChain产品或任何agent框架的新版本发布；文中提到的Deep Agents是LangChain自家harness，Claude Code是作为行业先例被提及。

Andrej Karpathy 行业动态 行业观点 补录 · 2026-11-01 发布 Andrej Karpathy

HackerTube. I was annoyed with YouTube's recommendations so I had Claude filter down 43M comments over 20 years of HN to 6,454 videos that keep being recommended. *Significantly* better viewing experience, ~2 hours with Opus 5.5: https://t.co/JIhXN7OSh1 - Excellent recs without any logins (state is kept in local browser session) - Thumbnail is a representative frame from middle of the video instead of the super duper A/B test hyper-optimized user uploads - Underlying data from the comment analysis as one zip file, point your Claude at it and ask for your own version - HackerTube Longs ✊ A bit more on the process: I use Claude Code (desktop app for Mac), Opus 5.5 on Medium effort as my default. I only talk to Claude and have it do everything, the only "manual work" I helped with in tandem was in the browser (reminiscent of MenuGen): 1) I had to create some kind of API key from Google Cloud UI to query YouTube for video metadata, 2) I booted up a VPS box for serving and 3) I bought the domain name. Once the box was up I gave Claude the IP and told it update, secure, harden, deploy and optimize the code, and it did the whole thing. Many awesome projects that would have normally taken weeks/months even can now be few-shotted for breakfast. What else are we not thinking of.

译文

HackerTube。我对 YouTube 的推荐感到烦了，于是让 Claude 把 HN 20 年来的 4300 万条评论筛选出 6454 个一直在被推荐的视频。

*明显*更好的观看体验，用 Opus 5.5 大约花了 2 小时： https://t.co/JIhXN7OSh1 - 无需任何登录即可获得出色的推荐（状态保存在本地浏览器会话中） - 缩略图是视频中间的代表性帧，而不是那些经过超级 A/B 测试超优化的用户上传缩略图 - 评论分析的底层数据打包成一个 zip 文件，让你的 Claude 读取它，让它生成你自己的版本 - HackerTube Longs ✊ 再补充一点过程： 我用 Claude Code（Mac 桌面应用），默认使用 Opus 5.5，Medium effort 模式。

我只和 Claude 对话，让它做所有事情，我唯一手动配合的部分是在浏览器里（有点像 MenuGen）：1）我不得不从 Google Cloud UI 创建某种 API 密钥来查询 YouTube 的视频元数据，2）我开了一台 VPS 用于托管，3）我买了域名。

事实摘要

北欧私募巨头EQT全球主席Jean Salata接受Semafor采访时表示，无论前沿实验室发生什么，AI仍将需要大量电力、能源、芯片和数据中心，EQT因此持有1000亿美元能源资产，这部分正成为AI发展的限制因素。

Salata用“bragawatts”形容大量并未兑现的算力签约，称签约与按时交付并接通电力是两件完全不同的事，并提醒公开市场上正有投资者在投资自己并不真正理解的东西。

EQT表示其数据中心92%的合同收入来自超大规模云服务商，公司刻意回避了Apollo、Blackstone等美国同行热衷的私人信贷业务，并称信贷是“beta业务”，非自身优势所在。

“bragawatts”及“签约不等于交付”属于EQT高管Salata的自述观点，反映大型机构投资者对当前AI数据中心签约潮的审慎态度，并非独立第三方验证的事实。
