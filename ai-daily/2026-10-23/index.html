Amazon SageMaker AI 模型/产品发布 AI 产品与工具 aws

Amazon SageMaker AI 正式发布无服务器模型定制训练会话，用户可自定义后训练循环且无需管理 GPU。

事实摘要

Amazon SageMaker AI 宣布其无服务器模型定制服务新增训练会话（training sessions），并于 2026 年 10 月 22 日正式全面可用。

用户可编写并协调自己的后训练循环，包括自定义损失函数、奖励信号或多轮强化学习，而 SageMaker AI 负责 GPU 分配、分布式执行、故障恢复和检查点存储。

该功能支持 SFT、DPO、RLVR、RLAIF 等技术，用户可选择 LoRA 或全量微调，初始支持 gpt-oss-20b、gemma-4-31B-it、Qwen3.6-27B 和 Qwen3.8-27B 模型，按 SageMaker AI 处理的 token 计费。

编辑解读

SageMaker AI 的训练会话把用户自定义训练循环（如 GRPO 的多轮采样、评分、更新）与托管基础设施解耦，适合后续跟踪其在多轮 RL 场景中的实际采用与可复现效果。

Canva 模型/产品发布 工程实践 TechCrunch

Canva 发布首个自研图像生成模型 Canva Craft，面向全部用户开放并计划提供 API 与 MCP 接入。

事实摘要

据 TechCrunch 于 2026 年 10 月 22 日报道，Canva 发布其首个自研图像生成模型 Canva Craft，向平台所有用户开放，并称将与 Google、OpenAI、ByteDance 和 Meta 的同类别模型竞争。

模型分两阶段工作：先解析提示并规划空间关系、相对比例、视觉层次与文本生成信息，再生成最高 2K 分辨率、约 30 种宽高比的图像；Canva 表示模型使用其模板库中的人工设计而非照片训练，生成图像可经 Canva Magic 转换为分层设计。

模型还将通过 Canva API 提供，并计划经 Canva 的 MCP 在 ChatGPT、Gemini 等第三方聊天机器人中支持图像生成；

低成本版本 Craftfast 与 Craft-ultrafast 即将发布，Leonardo.ai 研究人员参与了开发。

编辑解读

对开发者而言，Canva Craft 的实质看点不只是又一个文生图模型，而是 Canva 通过 API 与 MCP 把自研生成能力和设计模板资产变成可编程服务；第三方图像模型厂商在 Canva 这类垂直场景可能面临被自研模型替换的压力。

Canva 宣称的质量与成本优势尚无独立验证；TechCrunch 认为新模型可能帮助 Canva 节省第三方 API 成本，报道另提及 Canva 下调 2026 年增长预测、据外部分析师估值从 420 亿美元降至 350 亿美元。

OpenAI Agent/开发者基础设施 基础模型与技术 IT之家

OpenAI 宣布全面开放决策 API：基于 GPT-6 Luna，输入每百万 token 定价 0.1 美元。

事实摘要

当地时间 10 月 22 日，OpenAI 宣布全面开放决策 API（Decisions API），该 API 基于 GPT-6 Luna 构建，将模型能力聚焦于限定答案（bounded answers）的问题，支持文本、图像及结构化输入，协助应用与智能体做准实时决策。

OpenAI 称其响应速度比通过 Responses API 调用 GPT-6 Luna 最高提升 10 倍；

定价为输入每百万 token 0.1 美元、缓存命中输入每百万 token 0.01 美元，仅按输入 token 计费，输出 token 免费。

自公测以来，该 API 新增了原生 GPT-Live 集成、Prompt 缓存及美国与欧盟的推理数据驻留支持；开发者现可传入原生 JSON、在问题指令中包含图像，单次请求最多提交 400 个问题（为此前上限的两倍）。

OpenAI 表示正将该 API 应用于自身产品和业务工作流，并已在亚洲多个地区扩充服务容量以优化延迟。

编辑解读

决策 API 从公测走向全面开放，说明 OpenAI 在把智能体决策场景产品化，后续可对比其在真实任务中与通用 Responses API 的延迟与准确率差异。

事实摘要

NVIDIA于10月22日发布AIOps平台Minerva，连接基础设施与AI工作负载遥测，帮助运营团队更早发现问题，以GPU小时、goodput、集群可用时间与token产出为指标衡量并提升AI工厂产出(yield)。

Microsoft 研究/Benchmark AI + 行业赋能 IT之家

微软推出AI医疗诊断系统MAI-DxO：复杂病例诊断准确率83%，研究登《科学》

事实摘要

微软于当地时间10月22日宣布推出AI医疗诊断系统MAI-DxO（Microsoft AI Diagnostic Orchestrator），通过编排多个AI智能体模拟专家联合会诊，协同向患者问诊、开具化验检查并对潜在诊断展开辩论。

在基于NEJM复杂病例的模拟评估中，MAI-DxO诊断准确率为83%，高于可独立查阅参考资料的基层全科医生及普通内科医生的36%；此类病例在现实临床中通常由专科专家或多学科团队诊治，但专科医生未纳入本次对照。

在MIMIC-IV-ED急诊常见病例评估中，该系统诊断准确率达人类医生的1.7倍；微软称其成本仅为医生的一半甚至三分之一，能以更少的化验与诊疗操作精准锁定正确诊断。

研究成果发表于《科学》期刊，数据显示能力跃升主要归功于底层基础AI模型性能增强，编排架构进一步放大增益；微软对OpenAI、谷歌、Anthropic、Meta及DeepSeek的模型进行了测试，其中GPT-5及GPT-5.5表现最亮眼。

Airlock Agent/开发者基础设施 基础模型与技术 airlock.sorrel.systems

Airlock 发布：在 Mac 的隔离虚拟机中运行 Claude Code 或 Codex，并按 diff 逐文件审阅可保留的改动。

事实摘要

Airlock 在 Mac 端推出，将 Claude Code 或 Codex 放进本机虚拟机运行，基于项目副本工作，真实文件夹不会共享给 agent。 任务结束后，它给出每个被改动文件的 diff，由用户勾选需要的变更应用到项目并支持撤销。

它关闭逐个批准提示，从虚拟机操作系统内部记录进程、文件与网络访问，把非代码托管或包仓库类主机标记为风险，模型请求仍照常发往 Anthropic 或 OpenAI。 运行要求是 Apple silicon 芯片与 macOS 26 以上；

Xcode 项目可复用本机已装 Xcode，无需第二份拷贝。

编辑解读

Airlock 将 Docker Sandboxes 作为比较对象，差异点是逐文件预览、实际运行记录，以及带有本机 Xcode 的 macOS 会话；这些差异能否形成长期优势有待验证。

它自身也承认只“包住” agent 而不能让其变得可信：会话默认可访问公共主机，agent 对可达服务的外部操作在审阅前即已真实发生。
