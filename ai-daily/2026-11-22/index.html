OpenAI 监管/安全/隐私 政策、安全与社会影响 补录 · 2026-11-20 发布 OpenAI

OpenAI公布对抗蒸馏防护更新，称内部评估中GPT-6.2 Astra推理轨迹提取攻击成功率由54.0%降至0.2%。

事实摘要

OpenAI于11月20日发文，介绍其用对抗测试、模型训练、分类器与API层防护，检测和阻断针对“受保护推理”的对抗蒸馏。 OpenAI称，其已在GPT-6.2 Astra和GPT-6.2 Sol中加强了对受保护推理提取的防护。

OpenAI称，其在一项使用强自动化红队的内部自适应评估中测得，提取较早请求受保护推理的平均攻击成功率由GPT-6 Astra原防护的54.0%降至GPT-6.2 Astra更新防护的0.2%。

API把受保护推理绑定到生成它的对话历史，改写早前消息即丢弃其后推理，并阻止旧模型系列读取GPT-6.2 Astra与Sol的受保护推理。 OpenAI称其在平台上观察到多起未授权蒸馏活动，每周执法涉及数千至数万账户，并与其他模型提供商共享入侵指标。

编辑解读

该文在API层防护部分提到跨对话加密推理泄露攻击，并说明GPT-6.2 Astra和GPT-6.2 Sol将受保护推理绑定到生成它的对话历史。

联合国《特定常规武器公约》（CCW）日内瓦会议 监管/安全/隐私 政策、安全与社会影响 The Guardian

联合国自主武器谈判授权磋商未果，会议转而通过可能不具法律义务的“协商一致拟定”方案。

事实摘要

《卫报》报道称，为期一周的联合国《特定常规武器公约》（CCW）日内瓦会谈在凌晨5点前破裂，通宵磋商未能克服俄罗斯对自主武器谈判授权的反对。

尽管绝大多数国家希望达成通向有法律约束力条约的谈判授权，但CCW需协商一致，会议最终采纳更弱选项，授权仅为“以协商一致方式拟定”，可能不具任何法律义务。

报道称俄罗斯以拖延战术主导反对，美国等投资AI战争能力的军事大国也不愿承诺具约束力议定书，韩国、日本、土耳其、英国、法国和德国等同样主张非约束性安排。 CCW有128个缔约方、须全体一致才能通过声明，过去30年未通过任何规范武器的新法律；

100多个国家曾推动新法，巴西代表称相关武器已在被使用并继续开发。 报道还称以色列和美国已在加沙和伊朗使用AI辅助目标系统，并援引调查媒体报道称美军的目标是每小时执行1000次AI辅助目标决策。

编辑解读

CCW已就自主武器讨论13年，部分条约实质内容已基本确定；人权观察人士称类似条约可在15个月内谈成，并反驳美方提出的五年方案。 在共识机制下，少数反对者即可阻断授权，短期难形成具约束力的国际规则，出口管制与国别立法可能更趋碎片化。

Databricks 模型/产品发布 AI 产品与工具 补录 · 2026-11-19 发布 Databricks

Databricks 官方博客称，Genie Code 批量迁移功能已正式可用，可将整个文件夹的 Tableau 和 Power BI 报表转换为 AI/BI 仪表板。

事实摘要

Databricks 在官方博客表示，Genie Code 的批量仪表板迁移功能已正式可用：用户可指向包含 Tableau 或 Power BI 报表的整个文件夹，在一次运行中转换为 AI/BI Dashboards，并映射到指定的 catalog 与 schema。

此前 /importBI 流程一次只迁移一份报表；批量模式要求先把报表及配套数据源文件放入 Unity Catalog volume，Agent 会列出识别到的报表、询问目标位置，并把各报表作为后台任务排队处理。

官方同时提醒，“Completed”仅表示该报表运行结束，不代表每个可视化都已定稿；迁移后应逐份与原始报表对账，数据新鲜度、默认过滤器或 distinct count 等计算语义都可能造成数值差异。

编辑解读

相比此前用 /importBI 逐份迁移单个 Tableau 或 Power BI 报表，这篇博客介绍的是把同一迁移流程扩展到文件夹级批量处理。

Google Agent/开发者基础设施 Agent 技术 补录 · 2026-11-19 发布 WIRED

谷歌Chrome团队搭建完全受控的“镜像维度”互联网，用于训练和攻击测试其AI浏览智能体。

事实摘要

Kimi Code CLI v2.7.0 新增原生 Amazon Bedrock provider，改用 AWS 凭证链不再依赖独立 API Key。

事实摘要

AWS 官方博客介绍了 Kimi Code CLI v2.7.0 新增的原生 bedrock provider；

此前接入 Bedrock 需使用 type="openai" 或 "openai_responses" 的通用 provider，并自行配置区域 base_url 与 Amazon Bedrock API key。

新方式沿用标准 AWS 凭证链（默认链、命名 profile 或 IAM Identity Center SSO），provider 通过 @aws/bedrock-token-generator 生成短期 Bedrock API key 并按需续期，有效期最长 12 小时或等于 AWS 会话时长，取两者较短者。

文中以 Kimi K3.1 Pro Highspeed 为例，通过 global.moonshotai.kimi-k3.1 全局推理 profile 调用，该模型支持流式输出、可配置推理、图像输入和客户端工具调用，示例 config.toml 声明了 100 万 token 上下文。

限制写得比较清楚：桌面与网页端的 provider 创建界面目前未暴露该凭证链所需的全部环境字段，需直接编辑 config.toml；Kimi Code 不会自动探测 Bedrock 上多数模型的能力，需手动声明；凭证保护与权限最小化仍由用户负责。

编辑解读

这次更新的实质是把认证负担从自管的 Bedrock API Key 移到 AWS IAM 凭证链，对需要密钥轮换和最小权限的企业部署更友好。 但它只是接入层改动，模型能力没有变化；

长时运行的编码 agent 在短期 bearer token 续期和权限收敛上的实际体验，仍要通过真实使用检验。

LlamaIndex 博客解析 schema drift 检测，并给出在 LlamaParse 抽取输出层做结构校验的代码模式。

事实摘要

LlamaIndex 官方博客发布技术文章，说明 schema drift 指数据源结构偏离下游系统预期，并给出在 LlamaParse 文档抽取输出层做结构校验的代码模式。

文章把 schema drift 与数据质量问题区分开：前者关乎列是否存在、类型是否正确，后者关乎值本身；并把列删除与数据类型变更列为破坏性最大的两类，类型不符可能被静默转换、产出错误结果而不报错。

检测路径给出三种取舍：摄取时结构比对可能因新增列等非破坏性变化让管道整体停摆；统计画像需调参校准，文章称它是唯一能捕捉静默损坏的方法；schema registry 与 CDC 覆盖最全但需更多基础设施投入。

在文档抽取场景中，文章建议把校验施加于抽取后的结构化输出而非仅原始文档，逐批比对字段缺失、类型不符与多余字段。

编辑解读

对已在使用文档抽取管道的团队，把校验点放在抽取结构化输出上的做法可直接复用，但这是厂商博客的工程建议，并非新产品发布或第三方验证。
