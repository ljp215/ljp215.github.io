01
Qwen 模型/产品发布 IT之家

Qwen-Image-2.1 Pro/Turbo API 上线千问 AI 平台，Turbo 权重同步开放并支持 2K 图像生成与编辑

事实摘要

千问 AI 平台 10 月 11 日宣布 Qwen-Image-2.1 Pro 和 Turbo API 正式上线，开发者可通过 API 将图像生成与编辑能力接入应用，无需自行部署模型、管理推理环境；

同时 Qwen-Image-2.1-Turbo 模型权重同步开放。Qwen-Image-2.1 最多支持 10 张参考图输入，可通过圈选、涂抹和独立掩码指定编辑区域，并加强人像面部身份保留与商品文字、纹理、形态一致性。

Turbo 版基于 7B 视觉生成架构，去噪过程缩短至 8 步，支持 2K 图像生成与编辑。官方描述的场景包括设计、电商、营销和内容创作。

编辑解读

这次发布的重点不在生成质量参数，而在把图像生成变成可集成服务：API 免去部署，Turbo 用 8 步去噪换取更低推理成本，同时权重仍开放。对开发者而言，托管接入与自部署并行，后续比拼将回到生成质量、编辑可控性和实际推理成本的综合表现。

02
OpenAI 模型/产品发布 IT之家

OpenAI 将 GPT-6.1 Sol 默认上下文提升至 500k，较此前 272k 增加约 80%，并免收长上下文费用

事实摘要

OpenAI 工程负责人 Thibault Sottiaux（Tibo）宣布，将 Codex 和 Work 环境下 GPT-6.1 Sol 的默认上下文长度从 272k 提升至 500k，增幅约 80%。

官方称该调整可降低上下文压缩触发频率，更好支撑需要长期保留大量上下文与复杂细节的任务，并经测试认定该值对绝大多数用户是体验与性能的最佳平衡点。用户仍可手动设置，模型最大上限为 1M。

此外，从订阅扣除用量时 OpenAI 不再对 GPT-6.1 Sol 收取长上下文费用。该消息由 IT之家转述，尚无官方公告链接。

编辑解读

默认上下文长度从 272k 提到 500k，本质是产品层默认值调整，而非模型能力突破——最大上限仍为 1M。真正值得注意的隐藏信息是免收长上下文费用，这可能意味着 OpenAI 在订阅体系里把长窗口成本内部化，面向竞争而非技术领先。

蚂蚁集团旗下 AI 产品“灵光” 模型/产品发布 36kr.com

蚂蚁“灵光”开启新版本内测：转向长记忆个人智能体，对标 Meta Muse

事实摘要

据 36 氪援引接近项目人士消息，蚂蚁集团旗下 AI 产品“灵光”近日开启新版本小范围内测，新版对标 Meta 9 月推出的个人智能体 Muse。

升级核心是从能聊天、生成应用的 AI 助手，转向拥有长期记忆、可主动推进任务的个人智能体，并可通过调用 Skill 和 MCP 实现钉钉发消息、控制智能家居。

内测用例聚焦长程、变量多、需持续盯守的场景，如跟踪市场异动、管理钉钉打卡、航班延误/景区限流时重排路线。消息称该方向筹备约半年，计划本月全面开放。

编辑解读

灵光从“生成应用助手”转向长记忆、主动执行的个人智能体，是对 Meta Muse 路线的直接对标。当前只有内测口径，无实测表现；它能否把 MCP/Skill 调用沉淀为稳定日常体验，比“长期记忆”概念本身更值得跟踪。

OpenAI 将于 10月23日停用 GPT-4o 最早 API 快照，Keep4o 社区请愿开放权重

事实摘要

据量子位报道，OpenAI 将于 10月23日停用 GPT-4o 最早的 API 快照（2024-05-13 版本，即 4o 首次亮相版本），API 内其他版本仍可调用。

gbos-vm 项目 Agent/开发者基础设施 IT之家

开发者开源 gbos-vm：QEMU 适配让 Googlebook OS 登上 Apple Silicon Mac，支持 GPU 加速

事实摘要

开发者 Skylar Taylor-Barrick 开源 gbos-vm，用 QEMU 加载谷歌为戴尔 Googlebook 提供的官方恢复镜像，改造适配虚拟硬件，让 Googlebook OS 在 Apple Silicon Mac 上运行。

针对 Android 图形栈用 Vulkan、苹果用 Metal 的差异，项目搭建图形转换与共享机制，使虚拟机调用 Mac GPU 而非仅 CPU 渲染，可启动运行 Chrome。

要求至少 16GB 内存、预留约 60GB 存储，首次运行下载约 9GB 恢复镜像；不支持英特尔 Mac。已知限制包括显示刷新率上限 60 帧、音频不稳定、蓝牙无法连接真实设备、缺少 TPM 安全硬件；开发者建议仅用于开发测试，勿登录敏感账户；

项目与谷歌、戴尔无官方关联。

编辑解读

这次工作的实质是把厂商恢复镜像改造成可引导的虚拟系统，Vulkan→Metal 图形转换层才是真正的工程贡献，Googlebook OS 本身没有变化。缺少 TPM 与验证启动保护，方案只能用于开发测试，作为日常主力系统仍有明显缺口。

Open Academic Paper Gen Agent/开发者基础设施 qbitai

开源项目 Open Academic Paper Gen 发布：从全文核验引用，生成带出处的论文初稿

事实摘要

量子位报道，个人开发者“猫叔”发布开源多智能体论文写作工作流 Open Academic Paper Gen。该工具将论文初稿生成拆成九阶段：确定研究范围、检索文献、清理筛选、分析趋势、寻找切入点、列提纲、写作、核验和导出。

它从 OpenAlex、Crossref、Semantic Scholar、arXiv 检索文献，并整理成证据表。

特色是三道引用核验：检查引用是否存在、通过 Crossref 核对 DOI 身份、从全文定位段落判断原文是否真正支持引用观点，若有页码会标注 PDF 页码；证据不足时标为“无法判断”。

支持 OpenAI 和智谱 GLM，但论点核验、无引用陈述检查和模拟审稿仍需 OpenAI API Key。可导出 Markdown/LaTeX 及 RIS/BibTeX，支持人机确认和全自动两种模式。

编辑解读

这类工具的关键已从“生成初稿”转向“引用可溯源”：把核验从元数据层面推进到全文语义层面，并为人工复查提供页码抓手。但全文支撑判断仍依赖 LLM 能力，文章未给出核验准确率或错误率数据，实际可靠性需实测。

Khem Raj 行业动态 IT之家

高通工程师 Khem Raj 在 Linux Plumbers Conference 质疑 LTS 过时：AI 时代或更适合滚动更新

事实摘要

据 IT之家 10 月 11 日转述 Phoronix 报道，高通工程师 Khem Raj 在捷克布拉格举办的 Linux Plumbers Conference 上质疑 Linux LTS 发行版在生成式 AI 时代的适配性。

他认为 AI 编程智能体正加快 Linux 内核及相关开源项目的补丁提交速度，给开源维护者和发行版厂商带来沉重负担；滚动更新可减少补丁回溯、保持与上游较小分歧、实现更快安全修复，但认证和资格审查仍是挑战。

他建议重新思考 LTS 的实用性，特别是嵌入式发行版和社区较小的维护版本，也可尝试用生成式 AI 工具辅助 LTS 发布维护。

编辑解读

这是对发行版供应链成本结构的重新讨论：当补丁吞吐量被 AI 智能体抬高后，LTS 的稳定性承诺与回溯维护成本开始失衡。目前仍是个人观点，但值得跟踪它是否会转化为发行版策略调整或内核维护工具链的 AI 化。
