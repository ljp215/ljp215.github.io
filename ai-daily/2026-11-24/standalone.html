Anthropic Agent/开发者基础设施 Agent 技术 TechCrunch

Anthropic 推出 Claude Ship，由 AI Agent 审查、修复并按团队策略自动批准代码变更。

事实摘要

据 TechCrunch 2026 年 11 月 23 日报道，Anthropic 宣布推出 Claude Ship，一套用于自动化代码审查、修复与例行变更审批的 AI Agent 工具。

该产品由已正式可用的 Code Review 与两个处于 beta 的新 Agent 组成：负责处理 CI 失败、合并冲突和审查反馈的 PR Steward，以及按团队写入仓库文件的策略自动批准变更的 Claude Approvals。

审批策略可用自然语言编写，并可纳入 Code Review 的发现或 Anthropic 自有分类器的信号；官方建议先在只读观察模式运行、从单个仓库起步并设置月度支出上限。

Claude Ship 面向 Claude Team 与 Enterprise 套餐、GitHub 上的仓库开放，团队仍可控制运行位置、Quick/Standard/Deep 审查档位以及哪些变更需升级给人工决策。

编辑解读

真正的新意不在 Code Review，而在把合并前的放行权部分交给 Agent；观察模式、单仓库和支出上限这些护栏，也说明官方清楚误放行的代价。 TechCrunch 在报道中将 Anthropic 称为「新近上市」的 AI 公司。

OpenAI 监管/安全/隐私 政策、安全与社会影响 The Decoder

OpenAI首席科学家公开GPT系列log-perplexity内部数据，并呼吁前沿实验室约定共同安全上限。

事实摘要

OpenAI首席科学家Jakub Pachocki提议将perplexity作为衡量AI进展的行业通用指标，并在博客中公开OpenAI自报的GPT系列基座模型log-perplexity数据，范围覆盖至GPT-6之后的未发布模型。

按其描述，GPT-3.5在约0.99时实现流畅对话，GPT-4在约0.91时具备链式推理，低于0.8后在网络安全与数学领域出现变革性能力。

他称从约0.76 log-perplexity的模型开始，模型产出突破性数学结果，包括尚未完全验证的Navier-Stokes问题解答；

他预计0.68至0.7区间会出现现有测试可能覆盖不到的进一步变革性能力，并警告标准对齐审计可能更难奏效，主张前沿实验室约定在AI监控达到明确里程碑前共同遵守不越过的上限。

文章同时指出该指标的局限：不同实验室使用不同测试数据集，使直接比较更困难，该分数也不直接衡量实际任务表现。

编辑解读

perplexity长期是基座模型预测下一token的评测指标，此次被OpenAI与能力阈值及跨实验室安全上限绑定，可与Anthropic提出的可验证全球发展暂停设想对照观察。

Supertake 融资/收购/估值 行业 / 商业动态 TechCrunch

Supertake获2000万美元种子轮融资，用AI Agent把用户的市场观点转为股票组合

事实摘要

据TechCrunch报道，AI投资初创公司Supertake完成2000万美元种子轮融资，由Adjacent领投，Coinbase Ventures与USV参投，另有多位天使投资人参与。

其服务允许用户用自然语言描述对世界变化的判断，再由前沿AI模型与交易Agent反复迭代，转化为可投资的股票组合，目前已接入Coinbase和Robinhood。

公司称设置了未经用户明确同意不得由AI存取资金、组合漂移限制、资产允许与禁止名单、异常活动实时监控、交易规模上限，并让Agent看不到用户的券商凭证。 产品目前仍处于内测候补名单阶段，本轮融资之前公司已完成200万美元pre-seed轮。

编辑解读

这类产品的实际门槛不在模型能力，而在把Agent动作限制在可审计的护栏内：资金存取、可交易标的和单笔规模都由规则约束，而非交给模型自行判断。 创始团队称已让该系统管理数千至数十万美元自有资金，但这只是自报数据，不足以证明其在真实市场波动下的可靠性。

Z.ai 模型/产品发布 基础模型与技术 补录 · 2026-11-23 发布 simonwillison.net

Z.ai 上线 GLM-5.4：称其为首个采用循环 Transformer 架构的模型，目前需通过 Coding Plan 访问。

事实摘要

一篇发布于 2026 年 11 月 23 日的博文称，GLM-5.4 已可从中国 AI 实验室 Z.ai 获取，并称这是 Z.ai 首个采用循环 Transformer 架构的模型。

循环 Transformer 让一组共享权重的层运行多次迭代、细化上一轮的隐藏状态，从而在不增加参数量的情况下得到更深的网络。

博文作者称，GLM-5.4 目前无法通过常规 API 访问，他订阅 Coding Plan 后才经共享 API 调用，且开放权重尚未提供。 博文作者还提到，这是他过去一周内第二次提到循环 Transformer；

第一次是 Thinking Machines Lab 的 Inkling 2 Mini，出现在 11 月 20 日。

编辑解读

对开发者来说，更值得验证的是循环层能否在编码任务中提升推理质量，而不是只看作者生成的 Pelican 图对比；在缺少公开参数量与基准数据前，不宜把架构新鲜感当成实际能力提升。

Databricks Agent/开发者基础设施 工程实践 Databricks

Databricks 在 Apache Iceberg REST Catalog API 中支持 catalog labels，并以 Tag Exchange Beta 暴露 Unity Catalog 的表级和列级标签。

事实摘要

Databricks 宣布在 Apache Iceberg REST Catalog API 中支持 catalog labels，为平台、引擎和 Agent 提供表级与列级的业务用途、归属和分类上下文。

该标准在 Iceberg REST 的 LoadTable 响应中加入可选 labels 字段，用字符串键值对传递元数据，但不规定标签词汇和解释方式，由各平台决定如何使用并负责本地策略执行。

Databricks 同时以 Tag Exchange Beta 将 Unity Catalog 的表级和列级标签通过 catalog labels 暴露，Google Cloud、Salesforce、ClickHouse、Atlan 等参与推进这一互操作方向。

PyIceberg 已增加在 Python 中访问这些标签的支持，并计划在下一个 0.13 版本让应用检查表级和列级标签。

编辑解读

这项改动的核心是把治理上下文从单一目录变成跨引擎和 Agent 可读的开放接口，让数据发现、分类和访问策略复用同一套标签。 跨平台效果仍取决于各工具是否按本地规则解释并执行这些标签。

vLLM Agent/开发者基础设施 工程实践 补录 · 2026-11-23 发布 vllm

MoRI UMBP 工程测试：1.8 TB Agent KV 池直接放在 NVMe，Kimi-K3 在 MI355X 上与同容量 DRAM 池吞吐相差约 1%。

事实摘要

文章介绍在 AMD Instinct MI355X 上用 MoRI 的 UMBP 将 1.8 TB Agent 会话 KV 池直接放在 NVMe，取消主机 DRAM 层，仅保留约 80 GB DRAM 作写缓冲和读暂存。

在 AgentX 回放的 48、70、96 个并发会话下，Kimi-K3 吞吐与同容量 DRAM 池相差不超过 1%，另一组机器上 NVMe 高 0.4%—0.9%；kvlab 长提示 70 会话下 NVMe 落后 0.6%。

按列表价，可承受 Kimi-K3 每日 83 TB 写入的 SSD 约 5.9 万美元即可存一天 KV，而 1.8 TB DRAM 池约 7.6 万美元只存约 31 分钟。 作者也提醒每个 KV 块都要写盘、会磨损 SSD，计划用分布式池分散写入；

高负载下 64 GB 写缓冲仍是必要配置。

编辑解读

这项结果把 Agent KV 缓存的容量层级从“堆 DRAM”改成“按写入量买 SSD”，在给定长会话回放中吞吐基本不降。 但证据限于 MI355X、Kimi-K3 等配置和单次运行，生产部署仍要核算 SSD 磨损与持续写入成本。

swyx 行业动态 行业观点 补录 · 2026-11-22 发布 Swyx

OpenAI proposes perplexity as the universal metric for industry self regulation and pacing (as opposed to eg FLOPS) “Given that the main way new surprising capabilities emerge is by progress on compression, a measure rooted in perplexity could give us a shared benchmark for general intelligence, regardless of the degree of automation of the development process. Extrapolating from recent progress, we should expect further transformative capabilities as we enter the ~0.68-0.7 log-perplexity window.” this chart is one of the most beautiful ways to tell the story of the last 4 years. it also shows that a lot of the post training issues we debate is kinda the B plot to the overall A plot of large scale pretrain progress.

译文

OpenAI 提出将困惑度作为行业自我监管与节奏把控的通用指标（而非例如 FLOPS） “鉴于新的惊人能力主要通过压缩方面的进展而涌现，一个植根于困惑度的度量可以为我们提供一个关于通用智能的共享基准，无论开发过程的自动化程度如何。

从近期的进展外推，随着我们进入约 0.68-0.7 对数困惑度窗口，我们应当预期更多变革性能力。” 这张图是讲述过去四年故事的最美妙方式之一。它还表明，我们争论的许多后训练问题，在某种程度上只是大规模预训练进展这一整体主线剧情之外的支线情节。

编辑解读

对开发者的价值不在新模型，而在这套判断框架：预训练规模化仍被视作能力提升的主变量，困惑度则被推为可跨模型比较的代理；但困惑度能否跨分词器与数据集对齐，是采纳这一指标前的前置条件。
