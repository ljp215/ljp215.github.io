Amazon 监管/安全/隐私 政策、安全与社会影响 Ars Technica

亚马逊称攻击者用Cairn框架的AI Agent在极少人工监督下发现并利用开源医疗影像AI应用零日漏洞。

事实摘要

亚马逊称，攻击者让运行在开源渗透测试框架Cairn上的AI Agent仅凭“获取 shell 访问”的指令，自主发现并利用了东亚一所大学服务器上某开源医疗影像AI应用的零日漏洞。 这些Agent随后取得系统完整控制权；

Palo Alto Networks的研究人员还观察到Cairn曾与GLM 5.2、DeepSeek V4 Flash和DeepSeek V4 Pro配合使用。

文章称，该活动共对至少19家机构执行25次自主操作，至少10家被成功入侵，目标涉及半导体、国防和公民社会领域。

编辑解读

Cairn原本面向防御方，但文章明确指出其也被攻击者用于针对半导体、国防和公民社会机构的行动，攻防双用途风险已具象化。

Amazon 融资/收购/估值 算力硬件与基础设施 补录 · 2026-11-23 发布 TechCrunch · TechCrunch

亚马逊宣布收购 Decart 的 AI 芯片优化技术栈与团队，据彭博报道金额 75 亿美元。

事实摘要

亚马逊宣布收购以色列初创公司 Decart 的 Decart Optimization Stack（DOS）技术及相关研究工程团队，据彭博报道交易金额为 75 亿美元，亚马逊公告未确认具体价格。

DOS 是让 AI 模型在 Nvidia、亚马逊和谷歌硬件上更高效运行的软件，亚马逊称自 2025 年起已与 Decart 合作优化自家 Trainium 芯片。

亚马逊并不打算接手 Decart 的实时世界模型（如 Oasis 3）与视频生成业务，重点在芯片软件优化；同时其正准备把 Trainium 对外销售，与 Nvidia 竞争。

报道称 Anthropic 曾以相近价位尝试收购 Decart，Nvidia 也曾以 40 亿美元估值参与其 3 亿美元融资，并被列为潜在买家。

亚马逊高管 Peter DeSantis 称，每一点算力效率提升都意味着更好的训练、强化学习、更快的推理和更低成本的模型。

编辑解读

亚马逊 2015 年收购 Annapurna Labs 后形成自研芯片设计部门，Nvidia 则曾以 69 亿美元收购以色列芯片公司 Mellanox，本文把本次交易与这两条路径并列比较。

Z.ai（智谱） 模型/产品发布 基础模型与技术 补录 · 2026-11-23 发布 The Decoder

Z.ai推出750B参数GLM-5.4，以28层运行两遍、不增加参数的方式提升计算深度。

事实摘要

Z.ai推出750B参数的GLM-5.4，将28层共享层运行两次，在不增加参数的情况下增加计算深度，并用门控、共享KV缓存和稀疏注意力控制内存与算力开销。 据Z.ai，750B参数的GLM-5.4自称性能可与参数量远高于自身的模型相比；

团队将2月发布的GLM-5基座重训为循环模型。 Z.ai把GLM-5.4定位为“Generalized Coding”起点，称代码可生成视频、游戏和CAD模型。 目前公开基准仅来自30B测试模型，750B模型无分数也无独立评测；

GLM-5.4已在GLM Coding Plan、ZCode和Z.ai Chat提供，API和权重待后续发布，token定价未公布。

编辑解读

关键不在750B数字，而在用循环计算深度换参数效率；但750B模型尚无公开基准和独立评测，且文中指出OpenAI自GPT-6 Astra已采用类似架构。

Meta 模型/产品发布 Agent 技术 TechCrunch

Meta将AI助手Muse接入Instagram私信，在美国、加拿大、墨西哥、日本和新加坡开始推送。

事实摘要

Meta宣布把AI助手Muse接入Instagram私信，用户可在私信线程里直接与Muse对话，无需在Instagram和Muse独立应用之间来回切换。

据TechCrunch报道，用户可以让Muse补充帖子、地点或商品的背景信息，补看错过的其他私信，也可把Instagram帖子分享给Muse并要求其执行操作，例如把咖啡店加入墨西哥城行程或查找鞋类折扣。

该功能面向美国、加拿大、墨西哥、日本和新加坡的iOS与Android用户开始推送；同时Instagram收藏内容可由Muse整理为Collections，这一步先在美国和加拿大上线。

Meta表示用户在Instagram上的Muse体验仍由自己掌控，未经用户批准不会分享、发布或发送任何内容，用户也可要求Muse遗忘信息或撤销操作。

编辑解读

此次动作把Muse放进用户本就用来发现商品、地点和内容的Instagram场景，延续了Meta将AI助手嵌入既有高频入口、而非只依赖独立App的思路。

vLLM 研究/Benchmark 工程实践 补录 · 2026-11-23 发布 vllm

vLLM 在 AMD MI355X 上用 MoRI UMBP 把 1.8TB Agent KV 池全部放到 NVMe，Kimi-K3 吞吐与同容量 DRAM 池相差不到 1%。

事实摘要

vLLM 工程博客称，在 AMD Instinct MI355X 上使用 AMD 开源 MoRI 库中的 UMBP KV 池，把 1.8TB 的 Agent KV 缓存全部放在 NVMe 上。

在 Kimi-K3 上，48、70、96 并发会话下吞吐与同容量 DRAM 池相差不到 1%，结果来自两组不同机器的运行。

该 NVMe 池不设 DRAM 层，DRAM 只做 64GB 写缓冲和 16GiB 读暂存，约 80GB，不到池容量的 5%。

文章按列表价称，能承受 Kimi-K3 每日 83TB 写入的硬盘存一天 KV 约 5.9 万美元，而 7.6 万美元的 DRAM 池只存 31 分钟。

其代价是每个 KV 块都要写入硬盘、加速 SSD 磨损，作者计划以分布式池把写入分摊到更多 SSD。

编辑解读

这意味着在 Agent 长会话场景，KV 缓存的经济性会更多受 NVMe 按写入量计费和 SSD 磨损影响，而不只是按容量持有成本衡量。 但这些对比每次都是单次运行，且同一集群单一配置的运行间波动约 ±2.5%，不宜把结果直接外推为普遍规律。

LlamaIndex Agent/开发者基础设施 工程实践 补录 · 2026-11-24 发布 llamaindex

LlamaIndex 发文拆解表单 OCR 失效原因，主张用版式感知解析替代模板坐标抽取。

事实摘要

LlamaIndex 发文称，表单是多数企业中最高频的文档类型之一，也是 OCR 最常令人失望的场景，难点在标签与取值的对应、勾选框含义和手写内容，而非文字识别本身。

文章指出，传统按坐标划分区域的模板式 OCR 依赖最不稳定的版式属性，页面上新增一个字段就会让下方区域读到相邻字段的值，且不会报错。

其提出的流程是先做版式分析，按区域分派文字识别、手写识别与勾选标记识别，再用 schema 对齐抽取替代坐标定位并做校验。

演示中同一份贷款申请换成另一种版式后，LlamaCloud 以 agentic 档解析仍输出 [x]/[ ] 形式的勾选状态和带表头的表格。

编辑解读

把抽取目标从像素坐标换成带语义的字段描述，决定多来源、频繁改版的表单能否自动化；但演示只给出两种版式的等价取值，没有准确率数据，选型仍需用自建表单实测。

ShellBench 研究/Benchmark Agent 技术 TechCrunch

新基准 ShellBench：OpenAI、Anthropic 与 Meta 最先进模型日常任务失败率超三分之一。

事实摘要

据 TechCrunch 报道，新基准 ShellBench 由 OpenClaw Foundation、Parsewave、Hugging Face、Red Hat 与 UC Berkeley 研究者合作构建，基于逾 1000 万条匿名真实 Agent 交互评估日常个人任务。

该基准显示，OpenAI、Anthropic、Meta 的最先进模型失败率超过三分之一，全部被测模型中有 15.7% 的尝试至少违反一项安全要求。 得分最高的 OpenAI GPT-6 Astra 在相同条件下三次重复全部成功的比例不足一半；

约 10% 本可正确的尝试至少违反一项安全标准，例如 79.5% 的情况下未考虑接孩子放学。

研究者称模型选择对总体表现的影响大于 harness，但更强模型的成绩更依赖 harness：GPT-6 Astra 在 Pi 中胜过 Claude Fable 5.2、在 Claude Code 中反而更差，且测试未覆盖 Muse、Dots、Claude Duet 的原生 harness。

编辑解读

对做消费级个人 Agent 的团队，这份基准的价值不在排名，而在于它把日常琐事拆成带安全约束的多步任务，并显示同一模型换执行框架后成绩差距明显。

Simon Willison 于 2026 年 11 月 24 日发文，提出过去十二个月大模型与编码智能体出现了三个能力拐点。

三个拐点的共同主线是模型在工具调用与长程自主执行上的跃迁，从“给出建议”走向“直接交付结果”，但判断依据是作者个人体验而非统一评测。 作者自己仍未确定 Fable 5.2 是否算新拐点，说明这类拐点的划分离不开事后主观判断。
