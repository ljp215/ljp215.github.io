Agent 技术

AWS 博客详解 Amazon Bedrock 上 OpenAI 模型的 prompt caching 配置：六轮 agent 负载节省约六成输入成本。

AWS 官方博客介绍在 Amazon Bedrock 上运行 OpenAI 模型时，为 agent 工作负载配置 prompt caching 的模式与代码示例。 缓存机制分为隐式与显式两种：隐式由 Bedrock 决定可复用前缀的结束位置，显式由代码用 prompt_cache_breakpoint 标记，官方建议两者结合使用。 可复用的静态前缀需达到 1,024 个 token；测试中约 4,000 token 的工具与指令前缀首次请求写入 4,120 token，后续请求读取这些 token。

入选理由：对在 Amazon Bedrock 上构建多轮 agent 的开发者有直接参考价值：代码展示如何通过显式断点和隐式缓存降低重复读取工具、指令与历史的输入成本，并给出 GPT-6 Astra 在六轮工作负载下的对比数字。

AWS 官方博客发布工程方案，演示用单个 AWS CDK 应用在 Managed Amazon Bedrock Knowledge Base 上构建企业级 agentic retrieval：agent 在金融与天气两个知识库间路由，经 AgentCore Gateway（按 MCP 暴露为工具）调用 AgenticRetrieveStream，返回带引用的可溯源答案。 文章确认 AgenticRetrieveStream 是托管知识库的一等服务能力，负责多轮规划、工具式检索与带引用回答，但该能力与 AgentCore Gateway 集成仅在 MANAGED 类型知识库受支持，客户自管（DIY）知识库不支持；托管模式由服务方管理摄取、存储、索引与检索，无需自建向量库。 方案由同一 CDK 应用一并部署两个 CloudWatch 仪表盘（覆盖七层遥测）和按需、持续两种评测，运行时自动以 OpenTelemetry 埋点；文章称设计目标是解决单次检索 RAG 无法跨语料库综合、无法按问题选择数据源、无法二次检索的问题。

入选理由：对在 Bedrock 上做知识库问答的企业开发者，这是可直接复刻的托管 agentic retrieval 工程模板，跨库路由、检索编排、观测与评测一并交付，无需自研后再补观测；影响范围限定在 AWS Bedrock 用户，而非行业性新能力发布。
